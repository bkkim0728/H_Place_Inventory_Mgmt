# H Place 매장관리 — 프로토타입

헤어살롱 1개 지점의 재고를 관리하는 웹 앱입니다. 12개 지점으로 넓히는 것을 전제로 설계했습니다.

- **화면**: 정적 웹 앱 (`web/`) → Render Static Site (무료)
- **데이터·로그인**: Supabase (Postgres + Auth + Edge Function 1개, 무료 플랜)
- **코드**: GitHub

Supabase를 연결하지 않으면 **데모 모드**로 실행됩니다. 샘플 데이터가 브라우저에만 저장되어서 설치 없이 화면과 흐름을 확인할 수 있고, 화면 위쪽 **역할 보기**로 전체 관리자·지점 관리자·직원 화면을 바꿔 볼 수 있습니다.

## 기능

| 화면 | 내용 |
|---|---|
| 재고 현황 | 관리 품목 수, 재고 금액(매입가), 재고 부족·품절 수, 입고·출고 추이 그래프, 발주 필요 목록, 최근 입출고 |
| 재고 목록 | 검색, 카테고리·상태 필터, 정렬, 품목별 입출고 등록 |
| 입출고 내역 | 기간(오늘·7일·30일 또는 **직접 설정**: 시작일~종료일, 최대 1년)·구분·검색 필터, 등록 취소, 화면에 보이는 기록을 **엑셀(.xlsx)로 다운로드** |
| 판매 내역 | 모든 사용자: 기간(오늘·최근 7일·최근 30일·이번 달·지난달·직접 설정)별 판매 금액·건수·수량·건당 평균과 이전 기간 대비 증감, 제품별·담당 디자이너별 판매 순위, 판매 기록(취소 표시·취소 버튼), 담당 디자이너 필터·검색, 엑셀 다운로드 |
| 전체현황 | 전체 관리자: 운영 중인 모든 지점을 한 화면에. 기간(최근 7일·30일·이번 달·지난달·직접 설정 최대 1년)별 전체 총매출·시술 매출·제품 판매·재료비율과 이전 기간 대비 증감, 재고 금액·재고 경고·오늘 근무·시술 매출 입력률, 총매출 지점별 누적 막대(기간이 길면 주별·월별로 묶음)(마우스 올리면 지점별 금액), 지점별 성과 비교표(매출 비중·객단가·재료비율·재고·근무·입력률, 지점명을 누르면 그 지점 매장 레포트로), 전 지점 인기 제품, 확인이 필요한 항목, 엑셀·인쇄 |
| 매장 레포트 | 지점 관리자 이상: 하루 업무 요약(날짜 이동·인쇄). 총매출·시술 매출(POS 마감 금액·건수를 직접 입력, 객단가 자동)·제품 판매·재료 사용액과 지난주 같은 요일 대비 증감, 주간 비교(최근 7일 vs 이전 7일 막대 그래프와 총매출·시술 매출·건수·객단가·제품 판매·재료비 비교표), 구분별 입출고(건수·수량·금액), 근무/휴무자, 많이 판매·사용한 제품, 디자이너별 판매·재료 사용, 확인할 일(품절·안전재고 이하·보건증·시술 인원 없음), 폐기·실사·취소 기록 · **재료 사용 상세**(보고 있는 날·최근 7일·30일): 재료 사용액·건수·시술 1건당 재료비·재료비율, 시간대별/일별 그래프, 카테고리·디자이너·제품별 사용(현재고와 남은 일수), 사용 기록 검색, 엑셀 |
| 제품 관리 | 모든 사용자: **이 지점 사용** 켜기/끄기(끄면 그 지점의 재고 목록·입출고 등록에서만 숨김, 다른 지점은 그대로), **사용 안 함 제품 숨기기**(기본 켜짐, 화면 표시만 바뀌고 이 기기에 기억, 숨긴 개수와 '모두 보기' 표시) · 전체 관리자: 제품 등록·수정, 전 지점 사용 중지 · 지점 관리자: **새 제품 등록**(모든 지점에 재고 0으로 준비, 품목 코드는 카테고리별로 자동 부여: 클리닉 → CN-001, 소모품 → SP-001 …), 자기 지점 안전재고·보관 위치, **품목명·브랜드·카테고리·단위·매입가·판매가·고객 판매용은 자기 지점에만** 적용(다른 지점은 그대로, 목록에 "지점 설정"과 공통 값 표시, "공통 값으로 되돌리기"). 전체 관리자는 수정할 때 "이 지점만(기본) / 모든 지점 같은 값"을 고릅니다. 입출고 기록의 매입가·판매가, 입출고 내역·재고 목록의 이름·단위도 지점 값을 씁니다. 수정 창의 "사용 중"은 지점 관리자에게는 이 지점 사용 여부로 동작합니다. 품목 코드와 모든 지점 사용 중지는 전체 관리자만 · 전체 관리자: **지점별 가격 비교** 탭(제품별 공통 값과 지점별 매입가·판매가, ▲▼ 표시, 지점 간 차이, 가격이 다른 제품만 보기, 엑셀) |
| 카테고리 관리 | 전체 관리자: 카테고리 추가·이름 변경·순서 변경·삭제(제품이 없을 때만). 순서는 재고 목록·필터·입출고 등록 창에 그대로 적용. 행을 누르면 선택한 지점의 카테고리 제품 현황(재고·안전재고·상태·금액)을 팝업으로 표시 |
| 직원 관리 | 전체 관리자·지점 관리자: **시술 직원 · 스태프 현황** 대시보드(재직·오늘 근무(반차 표시)·휴직·평균 근속·평균 나이·보건증 확인, 시술 직원 직급 구성, 담당 시술별 전체/오늘 근무 인원과 '오늘 없음' 표시, 시술 직원 1명당 스태프, 근속·연령대 분포, 이번 달 생일과 D-day, 전체 지점 보기에서는 모든 지점 합계) · 지점 직원 카드(**직원 사진**, **생년월일**(만 나이, 이번 달 생일 표시, 관리자만 보임), 직급: 대표원장·수석 부원장·부원장·수석 스타일리스트·스타일리스트·디자이너·스태프, 담당 시술, 정기 휴무, 입사일·근속, 시술/제품 인센티브율, 미용사 면허번호, 보건증 만료일, 재직·휴직·퇴사). 요일별 근무 인원·디자이너 수와 휴무자를 보여 주는 **주간 근무 현황**(시술 인원(스태프 제외)이 한 명도 없는 요일은 빨갛게 표시), 보건증 만료·30일 안 만료·미등록 알림. 앱 계정이 없는 직원(인턴 등)도 등록합니다 · 전체 관리자: **지점 → 전체 지점**으로 모든 지점 직원 한 목록(소속 지점 표시), 지점별 인원 표(재직·시술 인원·스태프·오늘 근무·휴직·퇴사·보건증·평균 근속)와 직급 분포, 수정 창의 **소속 지점**으로 지점 이동 |
| 근무 현황 | 모든 사용자: 이번 주(월~일) 날짜별 실제 근무 인원·시술 인원·휴무자와 사유(정기 휴무·연차·반차·병가·교육 등), 날짜를 누르면 그날 근무 스케줄(근무/휴무·부재, 담당 시술, 메모). 이전·다음 주로 이동 |
| 근무표 | 모든 사용자(보기) · 지점 관리자 이상(수정): 월별 근무표. 정기 휴무 위에 날짜별 연차·반차·병가·교육·추가 휴무·대체 근무를 기록하고, 날마다 근무 인원과 시술 인원(스태프 제외)을 보여 줍니다(시술 인원 0명인 날 표시). 관리자에게는 **연차 현황**(근로기준법 입사일 기준 발생 추정, 사용·남은 일수)도 보입니다 |
| 실적·정산 | 전체 관리자: **전체 지점 / 선택 지점** 전환(기본 전체 지점) — 운영 중인 모든 지점의 총매출(시술+제품)·시술 매출·인센티브 합계·재료비율과 전월 대비, 지점별 정산 상태(확정/집계 중)·인원·총매출·매출 비중·1인당 매출·인센티브율·재료비율 비교표(지점명을 누르면 그 지점 정산으로), 지점별 매출 구성(시술/제품) 막대, 전 지점 TOP 10 직원, 전체 지점 CSV · 지점 관리자 이상: 월별 직원 실적과 인센티브. 시술 매출·건수·조정액은 POS 기준으로 입력하고, 제품 판매·재료 사용액은 입출고 때 고른 **담당 디자이너** 기준으로 자동 집계합니다. **정산 확정**으로 그 달을 고정하고(확정 취소는 전체 관리자), CSV로 내보냅니다 |
| 사용자 관리 | 전체 관리자만: 사용자 추가(아이디·비밀번호 발급), 아이디·이름·역할·지점·사용 여부·비밀번호 수정. 지점 관리자에게는 메뉴가 보이지 않고, 대신 **직원 관리**와 **지점 관리**를 씁니다 |
| 지점 관리 | 전체 관리자: 지점 추가·수정·운영 중지 · 지점 관리자: 자기 지점 이름·연락처·주소. 둘 다 **지점 사진**을 올리거나 지울 수 있고, 사진은 로그인 화면 배경으로 쓰입니다 |
| SNS 홍보 | 모든 사용자(승인·설정은 지점 관리자): 게시일별로 인스타그램(피드·캐러셀·릴스·스토리)·페이스북·틱톡·네이버 플레이스 게시물 초안을 **국내용(한국어) / 해외용(English, 네이버 제외)** 버튼으로 만듦. 초안은 **매장 데이터 30%**(근무표의 오늘·내일 근무 디자이너, 판매 내역 최근 4주 베스트 제품, 안전재고보다 넉넉한 판매 제품, 재료 사용 최근 4주 많이 한 시술)와 **트렌드 콘텐츠 70%**(`web/sns-trends.js`: 계절별 컬러, 유행 커트·펌, 전후 전환 릴스·GRWM·ASMR·투표/Q&A 스토리·카드뉴스 등 인기 형식, 해외용은 K-뷰티·서울 여행객 대상 — 실시간 수집이 아닌 라이브러리라 분기마다 업데이트)로 문구·해시태그·촬영 가이드·출처를 만들고, 목표를 채운 뒤에는 쓰지 않은 주제로 더 만들기. 국내용·해외용 해시태그는 따로 설정. 하루 목표(기본 12개)·지점 해시태그·계정 이름·문구 톤은 SNS 설정. 미리보기로 수정 → 지점 관리자 승인·반려(사유)·모두 승인 → 문구 복사해 각 SNS에 올린 뒤 게시 완료 표시. 고객이 나오는 게시물(시술 과정·비포 애프터)은 **고객 게시 동의**(사진/영상 범위·얼굴 노출·유효 기간)를 연결해야 승인되고, 동의 철회 시 승인된 게시물은 승인 대기로 되돌아감. **홍보 영상 보관함**(비공개 Storage `sns-media` 버킷, 이 지점 직원만: 영상·사진 올리기 100MB 이하, 썸네일·재생·다운로드, 고객 등장 영상은 게시 동의 연결 필요, 게시물에 연결하면 미리보기 재생과 카드의 [영상 보기], 승인·게시 완료 게시물에 연결된 영상은 삭제 불가). 메뉴 배지: 관리자는 승인 대기, 직원은 게시 전 수 |
| SNS 트렌드 | 모든 사용자: 매주 월요일 올라오는 **국내 미용·뷰티 SNS 마케팅 동향 주간 보고서**(`web/trends/*.json`)를 **카드뉴스 16장**으로 보여 줌(PC는 격자, 휴대폰은 좌우로 넘기는 카드) — 표지·핵심 3줄·숫자 인포그래픽·키워드 클라우드, 네이버 플레이스·인스타그램·유튜브 쇼츠·틱톡·메타 광고별 동향(상승/유지/하락)과 커뮤니티 분위기 막대, **커뮤니티·댓글 분석**(유튜브·인스타·네이버·틱톡·메타·StockTwits·Benzinga, 말풍선 요지), 투자자 커뮤니티 동향(종목 타일), 헤어 컬러 스와치, 외국인·해외 동향, H Place 실행 제안(체크리스트, 이 기기에 저장), 다음 주 관찰 포인트, 번호로 연결된 출처 목록, 인쇄. 새 보고서가 올라오면 메뉴에 N 표시. 공개 웹 자료의 정성 요약이며 플랫폼 내부 데이터·투자 조언 아님 |
| 사용 매뉴얼 | 모든 사용자: 왼쪽 메뉴 맨 아래(도움말). **업무 프로세스별**로 구성 — ① 제품관리(카테고리·제품 등록 → 지점 설정 → 입고 → 사용·판매·폐기 → 재고 확인·실사 → 입출고 내역·취소 → 판매 내역 → 지점별 가격 비교) ② 근무관리(계정 → 직원 등록 → 근무표 → 근무 현황 → 실적·정산 → 전 지점 직원 현황) ③ 매장 레포트 확인(시술 매출 입력 → 요약·전주 대비 → 주간 비교 → 재료 사용 상세 → 근무·제품·확인할 일 → 지난 날짜·인쇄 → 전체현황) ④ SNS 홍보(SNS 설정 → 초안 자동 만들기 → 수정·동의 연결 → 승인·반려 → 게시·완료 표시 → 동의 철회). 단계 흐름도를 누르면 해당 안내가 펼쳐지고, 내 권한에 맞는 단계만 번호를 매겨 보여 줌. 검색, 해당 화면으로 바로 가기, 용어, 자주 묻는 질문, 인쇄 |

**담당 디자이너**: 시술 사용·판매를 등록할 때 담당 디자이너를 고를 수 있습니다(선택). 판매는 그때의 판매가도 함께 기록해 나중에 가격이 바뀌어도 실적이 달라지지 않습니다.

**입출고 구분**: 입고 · 시술 사용 · 판매 · 폐기 · 재고 실사(지점 관리자 이상, 실제 센 수량으로 맞춤)

## 권한 체계

| | 전체 관리자 (`admin`) | 지점 관리자 (`manager`) | 직원 (`staff`) |
|---|---|---|---|
| 지점 | 추가·수정·운영 중지 (전 지점) | 자기 지점 이름·연락처·주소 수정 | — |
| 직원 기록 | 모든 지점 | 자기 지점 (인센티브율이 있어 직원은 볼 수 없음) | — |
| 사용자(로그인 계정) | 사용자 추가, 모든 사용자의 아이디·이름·역할·지점·사용 여부·**비밀번호** 수정 | 화면 메뉴 없음 (계정 변경은 전체 관리자에게 요청) | — |
| 제품 | 제품 등록·수정, 카테고리 관리, 전 지점 사용 중지 | 새 제품 등록, 제품 정보 수정(품목 코드 제외), 자기 지점 안전재고·보관 위치·사용 여부 | 자기 지점 사용 여부 |
| 재고 | 전 지점 (상단에서 지점 선택) | 자기 지점, 재고 실사, 모든 기록 취소 | 자기 지점 입고·사용·판매·폐기, 본인 기록 10분 안 취소 |

**계정은 전체 관리자가 만듭니다.** 가입 화면은 없습니다.

1. 전체 관리자가 **사용자 관리 → 사용자 추가**에서 아이디, 이름, 비밀번호, 역할, 지점을 정합니다. **자동 생성** 버튼으로 읽기 쉬운 10자 비밀번호를 만들 수 있습니다.
2. 아이디와 비밀번호를 본인에게 전달하면, 로그인 화면에서 **아이디**로 바로 로그인합니다.
3. 비밀번호를 잊으면 전체 관리자가 **사용자 관리 → 수정 → 비밀번호 재설정**에서 새 비밀번호를 정해 줍니다.

아이디는 내부적으로 `<아이디>@hplace.local` 이메일 계정입니다. 아이디를 바꾸면 이 이메일도 함께 바뀝니다.

**잠김 방지 규칙**: 누구도 자기 자신의 역할·지점·사용 여부를 바꿀 수 없고(아이디·이름·비밀번호는 바꿀 수 있음), 마지막 전체 관리자는 강등하거나 중지할 수 없습니다. 사용 중지된 계정은 로그인해도 아무것도 볼 수 없습니다.

모든 규칙은 화면이 아니라 **DB 함수와 RLS**, 그리고 **Edge Function**에서 검사합니다. 화면을 조작해도 권한 밖의 작업은 거부됩니다.

**왜 Edge Function이 필요한가요?** 다른 사람의 계정을 만들거나 비밀번호를 바꾸려면 Supabase의 `service_role` 키가 필요합니다. 이 키는 모든 보안을 우회하므로 브라우저에 두면 안 됩니다. [`supabase/functions/admin-users`](supabase/functions/admin-users/index.ts)는 Supabase 안에서 실행되며, 요청한 사람이 **사용 중인 전체 관리자인지 확인한 뒤에만** 계정 생성·아이디 변경·비밀번호 변경을 합니다. 키는 함수 밖으로 나가지 않습니다.

## 데이터 설계

```
branches ─┬─ profiles (사용자 ↔ 아이디·지점·역할·사용 여부)
          ├─ inventory (지점별 현재고·안전재고·위치) ── products (전 지점 공용 품목) ── categories
          └─ stock_movements (모든 재고 변동 기록)
```

- 모든 테이블에 **Row Level Security**를 적용해서 사용자는 배정된 지점의 데이터만 봅니다.
- 앱은 테이블을 직접 수정할 수 없습니다. 모든 변경은 역할을 검사하는 DB 함수(`record_movement`, `revert_movement`, `save_product`, `set_branch_item`, `save_branch`, `save_category`, `delete_category`, `reorder_categories`, `update_user`, `list_users`)와 `admin-users` Edge Function으로만 합니다. 그래서 재고 변동은 **모두 기록**되고 재고가 0 밑으로 내려가지 않습니다.
- 취소는 기록을 지우지 않고 **반대 기록을 추가**합니다. 이력은 수정되지 않습니다.
- 제품은 카테고리 **이름**을 외래 키로 참조합니다. 카테고리 이름을 바꾸면 제품에 자동으로 반영되고(`on update cascade`), 제품이 있는 카테고리는 삭제되지 않습니다.
- 지점 간 이동(`transfer_in` / `transfer_out`)은 다음 단계를 위해 자리만 만들어 두었습니다.
- **지점 사진**은 Supabase Storage의 공개 버킷 `branch-photos`에 `<지점 id>/<파일>`로 저장됩니다. `schema.sql`이 버킷과 권한 정책을 함께 만듭니다(JPG·PNG·WEBP, 5MB 이하). 앱이 올리기 전에 긴 변 1920px JPEG로 줄이므로 한 장에 보통 수백 KB이고, 무료 플랜 저장 용량(1GB)에 여유가 있습니다.
  - 올리기·지우기: 전체 관리자, 또는 그 지점의 지점 관리자만 (`set_branch_photo` 함수와 Storage 정책에서 검사)
  - 로그인 화면: 로그인 전에도 `login_photos()` 함수로 **운영 중인 지점의 이름과 사진 경로만** 읽습니다. 이 기기에서 마지막으로 쓴 지점의 사진을, 처음이면 사진이 있는 지점 중 하나를 보여 줍니다.
- **직원 사진**은 개인정보라서 **비공개** 버킷 `staff-photos`에 `<지점 id>/<직원 id>/<파일>`로 저장합니다. 공개 주소가 없고, 전체 관리자와 그 지점 관리자만 1시간짜리 서명 링크로 봅니다. 앱이 가운데를 정사각형으로 잘라 480px JPEG로 줄여 올립니다(보통 수십 KB). 직원 기록을 지우면 사진 파일도 함께 지웁니다.
  - 사진은 공개 URL이라 주소를 아는 사람은 볼 수 있습니다. 매장 외관·인테리어처럼 공개돼도 괜찮은 사진을 올려 주세요.

### 기존 설치를 업데이트할 때

새 기능(지점 사진, 직원 관리 등)이 추가되면 **SQL Editor에서 최신 `schema.sql`을 다시 실행**하세요. 여러 번 실행해도 안전하고 기존 데이터는 그대로 둡니다.

## 설치 순서

### 1. Supabase 프로젝트 만들기

1. <https://supabase.com> 에서 가입 후 **New project**를 만듭니다. 지역은 `Northeast Asia (Seoul)`을 권장합니다.
2. 왼쪽 메뉴 **SQL Editor**에서 [`supabase/schema.sql`](supabase/schema.sql) 전체를 붙여 넣고 **Run**을 누릅니다.
3. 이어서 [`supabase/seed.sql`](supabase/seed.sql)을 실행합니다. 1호점과 샘플 품목 30개, 14일치 샘플 입출고가 들어갑니다. (실제 운영 전에는 생략하거나 품목을 바꿔서 실행하세요.)
4. **Authentication → Sign In / Providers → Email**에서 **Allow new users to sign up**을 **끕니다**. 계정은 전체 관리자만 만듭니다.
5. **Edge Functions → Deploy a new function → Via Editor**에서 함수를 만듭니다.
   - 이름: `admin-users` (정확히 이 이름)
   - 코드: [`supabase/functions/admin-users/index.ts`](supabase/functions/admin-users/index.ts) 전체를 붙여 넣고 **Deploy**
   - **Verify JWT**는 켜 둡니다 (기본값). 로그인한 사용자만 호출할 수 있습니다.
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`는 Supabase가 자동으로 넣어 주므로 따로 설정하지 않습니다.
   - 아이디 도메인을 `hplace.local`이 아닌 값으로 쓰면 **Edge Functions → Secrets**에 `LOGIN_DOMAIN`을 같은 값으로 추가합니다.

   CLI를 쓴다면 `supabase functions deploy admin-users`로도 배포할 수 있습니다.

### 2. 첫 전체 관리자 만들기 (한 번만)

로그인 화면은 **아이디** 또는 이메일을 받습니다. 아이디 `h001`은 내부적으로 `h001@hplace.local` 계정으로 로그인합니다. (도메인은 Render 환경 변수 `LOGIN_DOMAIN`으로 바꿀 수 있습니다.)

1. **Authentication → Users → Add user → Create new user**
   - Email: `h001@hplace.local`
   - Password: 사용할 비밀번호 (이 저장소에는 비밀번호를 적지 않습니다. 6자 이상)
   - **Auto Confirm User** 체크 — 실제로 없는 메일 주소라 인증 메일을 받을 수 없습니다.
2. **SQL Editor**에서 전체 관리자로 지정합니다.

```sql
update public.profiles
   set role = 'admin', branch_id = null, login_id = 'h001', full_name = '본사 관리자'
 where user_id = (select id from auth.users where email = 'h001@hplace.local');
```

3. 앱 로그인 화면에서 아이디 `h001`과 비밀번호로 로그인합니다.

> **비밀번호 권장**: 전체 관리자는 모든 지점의 데이터와 사용자를 바꿀 수 있고 사이트는 인터넷에 공개됩니다. 숫자만 6자리인 비밀번호는 추측 공격에 약하니, 운영 전에는 영문·숫자·기호를 섞은 12자 이상으로 바꾸세요. 로그인한 뒤 **사용자 관리 → 내 계정 수정 → 비밀번호 재설정**에서 바꿀 수 있습니다.

> Supabase가 `hplace.local` 주소를 받지 않으면 회사가 가진 도메인(예: `hplace.co.kr`)으로 계정을 만들고 Render 환경 변수와 Edge Function Secret의 `LOGIN_DOMAIN`을 같은 값으로 설정하세요.

이후 사용자는 모두 앱의 **사용자 관리 → 사용자 추가**로 만듭니다.

### 3. Render에 배포하기

**Render → New → Static Site**에서 이 저장소를 연결하고 아래처럼 설정합니다.

| 항목 | 값 |
|---|---|
| Branch | 배포할 브랜치 |
| Build Command | `node salon/scripts/build-config.mjs` |
| Publish Directory | `salon/web` |
| Environment | `SUPABASE_URL` = Project URL, `SUPABASE_ANON_KEY` = anon public key, (선택) `LOGIN_DOMAIN` = 아이디 로그인용 도메인, 기본 `hplace.local` |

두 값은 Supabase **Project Settings → API**(또는 **Connect**)에서 확인합니다. anon key는 브라우저에 공개되도록 만들어진 키이고 데이터는 RLS로 보호됩니다. **`service_role` 키는 절대 넣지 마세요.**

환경 변수를 비워 두면 데모 모드로 배포됩니다.

### 4. 로컬에서 실행하기

```bash
cd salon/web
python3 -m http.server 8000   # http://localhost:8000
```

Supabase에 연결하려면 `web/config.js`에 URL과 anon key를 넣습니다. (배포 시에는 빌드 명령이 이 파일을 환경 변수로 다시 만듭니다.)

## 실제 운영 전환 — 테스트 데이터 정리

베타 테스트 기간에 쌓인 한 지점(예: 본사)의 거래 기록을 지우고 깨끗한 상태로 시작하려면 `supabase/reset_branch_test_data.sql`을 씁니다.

- **지우는 것 (정한 지점만):** 입출고 기록 전체, 현재고(0으로), 시술 매출 입력, 월 실적·정산 확정, SNS 홍보 게시물·고객 게시 동의 기록, (선택) 근무표 기록
- **그대로 두는 것:** 지점 정보·사진, 로그인 계정, 카테고리, 제품 목록과 지점 설정(안전재고·보관 위치·지점 가격·사용 여부), 직원 정보, SNS 설정, 다른 지점의 모든 데이터

1. Supabase **SQL Editor**에 파일 내용을 붙여 넣습니다.
2. **[1단계]**의 `'본사'`를 정리할 지점명 또는 지점 코드로 바꾸고, 그 부분만 선택해 실행합니다. 지울 건수가 나오고, 이 단계에서는 아무것도 지우지 않습니다.
3. 백업: **Table Editor**에서 `stock_movements`, `daily_sales`, `staff_monthly`를 CSV로 내려받아 둡니다. 앱의 입출고 내역·판매 내역 엑셀 다운로드도 좋습니다.
4. **[2단계]**의 `v_branch`에 같은 지점명을 넣고, `v_confirm`을 `'예'`로 바꿉니다. 근무표도 지우려면 `v_schedule`을 `true`로 바꿉니다. 그런 다음 [2단계]를 실행합니다.
5. **[3단계]**로 모두 0건이 되었는지 확인합니다.

`v_confirm`이 `'예'`가 아니거나 지점을 찾지 못하면 아무것도 지우지 않고 멈춥니다. 한 번 지운 데이터는 되돌릴 수 없습니다.

### 지점 운영 시작 정리 (제품 목록까지) — `supabase/reset_branch_for_launch.sql`

테스트 기간이 끝나고 한 지점(예: 서초 아크로비스타점)을 실제 운영으로 시작할 때 씁니다. 위 스크립트와 달리 **직원 정보·근무표·SNS 홍보는 그대로** 두고, **제품 목록까지** 정리합니다.

- **지우는 것 (정한 지점만):** 입출고 기록 전체, 시술 매출 입력, 월 실적·정산 확정, 제품 목록
  - 다른 지점에서 한 번도 쓰거나 설정한 적 없는 제품 → 제품 자체를 삭제
  - 다른 지점에서 쓰는 제품 → 남기고 이 지점에서만 초기화(재고·안전재고 0, 보관 위치·지점 가격 없음)하고 '사용 안 함'으로 숨김
- **다른 지점 보호:** 실행 전후에 다른 지점의 입출고·재고·제품·매출·실적·카테고리를 비교해 하나라도 달라지면 전체를 취소합니다. 기준일(`v_cutoff`, 기본 2026-09-27) 이후 기록이 이 지점에 있으면 실제 데이터가 섞인 것으로 보고 멈춥니다. 제품을 전혀 삭제하지 않으려면 `v_products`를 `false`로 둡니다(이 지점에서만 초기화·숨김).

1. 파일의 `'서초 아크로비스타점'`을 지점 관리 화면의 지점명(또는 지점 코드)과 똑같이 모두 바꿉니다.
2. **[1단계]** 두 쿼리를 하나씩 실행해 지울 건수와 제품별 처리(삭제/남김·숨김, 사용 중인 다른 지점)를 확인합니다. 기준일 이후 건수는 0이어야 합니다.
3. 백업: **Table Editor**에서 `products`, `inventory`, `stock_movements`, `daily_sales`, `staff_monthly`를 CSV로 내려받습니다.
4. **[2단계]**의 `v_confirm`을 `'예'`로 바꾸고 [2단계]만 실행합니다. **[3단계]**로 결과를 확인합니다.
5. 앱에서 실제 제품을 등록(또는 '사용'으로 켜기)하고, 매장의 실제 수량을 **재고 실사**나 **입고**로 입력하면 운영 시작 재고가 됩니다.
